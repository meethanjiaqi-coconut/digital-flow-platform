# 风暴潮数字流场数据转换与发布说明

> 交接对象：河口院模型计算和数据发布人员  
> 工具：`tools/preprocess_flowfield.py`  
> 目标：将模型生成的 Tecplot ASCII DAT 转换成前端可渲染的压缩网格和逐时帧，并发布到数字流场服务

## 1. 职责边界

河口院负责：

1. 永久保存原始模型 DAT。
2. 保证 DAT、网格和时次数据符合本说明要求。
3. 在模型结果生成后运行转换发布脚本。
4. 为每次模型运行提供稳定且唯一的 `sourceRunId`。
5. 对脚本输出的校验结果负责，出现错误时不要跳过校验强行发布。

数字流场服务负责：

1. 接收转换后的共享网格和独立压缩帧。
2. 校验长度、gzip 和双重 SHA-256。
3. 向前端提供只读接口。
4. 只保存最近 100 个可直接渲染的场次。

数字流场服务不接收、不保存原始 DAT。

## 2. 交付文件

河口院需要取得以下两个文件：

```text
tools/preprocess_flowfield.py
tools/requirements-flowfield.txt
```

建议部署目录：

```text
flow-field-publisher/
  preprocess_flowfield.py
  requirements-flowfield.txt
  grid/
    grid-wgs84.shp
    grid-wgs84.shx
    grid-wgs84.dbf
    grid-wgs84.prj
  output/
```

脚本实际读取 `.shp` 主文件；建议仍将同名 `.shx/.dbf/.prj` 一并归档和交付，避免网格资料不完整。

## 3. Python 环境部署

### 3.1 环境要求

- 64 位 Python 3.11 或 Python 3.12。
- NumPy 2.3.2。
- 能通过 HTTP 访问数字流场服务。
- 运行账号对脚本输出目录具有读写权限。
- 建议每个发布节点使用独立虚拟环境。

脚本不需要 GDAL、GeoPandas 或 ArcPy。

```powershell
cd D:\flow-field-publisher

.\.venv\Scripts\Activate.ps1

```

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-flowfield.txt
```

```bash
cd /opt/flow-field-publisher

python3.12 -m venv .venv
source .venv/bin/activate

python -m pip install --upgrade pip
```

## 4. 输入数据要求

### 4.1 DAT 总体要求

DAT 必须是 Tecplot ASCII 文本格式，并采用 BLOCK 数据排列。

每个 DAT 可以包含多个 `ZONE`。同一批发布的多个 DAT 会按文件名排序，然后按每个文件内部的
ZONE 顺序读取。

所有 DAT 必须满足：

- 节点数 `N` 相同。
- 单元数 `E` 相同。
- 网格连接关系相同。
- 单元顺序相同。
- 时次严格递增。
- 默认要求相邻时次正好间隔 1 小时。
- 数值中不能包含 `NaN` 或 `Inf`。
- 文件扩展名可以是 `.DAT` 或 `.dat`。

当前真实数据基准为：

```text
72 个时次
38,081 个节点
71,958 个单元
```

脚本支持按实际 DAT 头读取规模，但节点数不能超过 65,535，因为渲染网格索引使用 `uint16`。

### 4.2 DAT 头和 ZONE 时间格式

DAT 文件前 1024 个字符内必须包含：

```text
N=38081, E=71958
```

允许 `N=`、`E=` 后存在空格，但必须保留逗号分隔。

建议保持当前已经验证通过的头部结构：

```text
TITLE="THE FEM TECPLOT DATA"
VARIABLES="X","Y","Z","Z1","U","V"
ZONE T="2026- 7- 9  8:00:00" , N=38081,E=71958
ZONETYPE=FEquadrilateral,DATAPACKING=BLOCK
VARLOCATION=([4-6]=CELLCENTERED)
```

`VARIABLES` 的顺序必须为 `X、Y、Z、Z1、U、V`。其中前三项为节点量，后三项为单元中心量。
现有模型文件中的 `VARLOCATION=([4-12]=CELLCENTERED)` 也已经验证可转换；脚本以实际数字块顺序为准。

每个时次必须使用以下 ZONE 标题形式：

```text
ZONE T="2026- 7- 9 08:00:00"
```

也支持补零形式：

```text
ZONE T="2026-07-09 08:00:00"
```

时间按北京时间解释，转换后写为 ISO 8601 `+08:00`。

不要使用不含日期的标题，例如：

```text
ZONE T="08:00"
```

### 4.3 第一个 ZONE 的数值块顺序

每个 DAT 的第一个 ZONE 必须包含完整网格和数据，数值顺序固定为：

```text
节点 X      float[N]
节点 Y      float[N]
节点 Z      float[N]
单元 Z1     float[E]
单元 U      float[E]
单元 V      float[E]
单元连接表   int[E * 4]
```

因此第一个 ZONE 的数字总数必须为：

```text
3 * N + 3 * E + 4 * E
```

字段含义：

| 字段 | 含义 | 单位 |
|---|---|---|
| X | 节点 X 坐标 | 与模型输出一致，脚本最终经纬度以 Shapefile 为准 |
| Y | 节点 Y 坐标 | 与模型输出一致，脚本最终经纬度以 Shapefile 为准 |
| Z | 节点底高程，脚本内部字段名为 `zb` | m |
| Z1 | 单元水位 | m |
| U | 单元东向/模型 X 方向流速分量 | m/s |
| V | 单元北向/模型 Y 方向流速分量 | m/s |

连接表要求：

- 节点编号从 1 开始。
- 四边形写 4 个不同节点。
- 三角形也占 4 个位置，第 4 个节点必须重复第 1 个节点。
- 最大节点编号必须等于 `N`。

### 4.4 同一 DAT 的后续 ZONE

同一个 DAT 内，从第 2 个 ZONE 开始只包含：

```text
单元 Z1 float[E]
单元 U  float[E]
单元 V  float[E]
```

每个后续 ZONE 的数字总数必须为：

```text
3 * E
```

注意：每一个新 DAT 的第一个 ZONE仍必须重新包含完整网格和连接表。

### 4.5 Shapefile 网格要求

网格必须是 WGS84 经纬度 Polygon Shapefile。

具体要求：

- Shape Type 必须是 Polygon，即类型 5。
- 每个要素只能有一个 Part。
- 每个要素对应一个 DAT 单元。
- Shapefile 要素数量必须等于 DAT 的 `E`。
- Shapefile 要素顺序必须与 DAT 单元顺序一致。
- 单元只能是三角形或四边形。
- Polygon 环必须闭合。
- 坐标单位为度。
- 相邻单元共享节点的经纬度偏差应小于 `1e-6` 度。

脚本会利用 DAT 连接表和 Shapefile Polygon 环重建唯一节点经纬度，并自动判断环点旋转和正反方向。

如果 Shapefile 重新导出后改变了要素顺序，即使空间图形看起来相同，也不能直接用于发布。

## 5. 转换后的数据规则

### 5.1 干湿判断

脚本先计算单元平均底高程，然后：

```text
水深 = Z1 - 单元平均 Z
```

当：

```text
水深 >= 0.05 m
```

判定为湿单元，否则为干单元。

### 5.2 量化

```text
水位精度：0.01 m
U/V 精度：0.001 m/s
干单元水位：-32768
干单元 U/V：0
```

单帧解压后布局为小端序：

```text
Z1 int16[E]
U  int16[E]
V  int16[E]
```

脚本会在转换时检查量化值是否超出 `int16` 范围。超出时直接失败，不会截断数值。

### 5.3 压缩

- 每帧单独使用 gzip 压缩。
- gzip 时间戳固定为 0，相同输入会得到确定性压缩结果。
- 默认 gzip 压缩级别为 6。
- 网格单独生成 `mesh.bin.gz`。
- 相同网格使用同一个 `meshId`，服务端不会重复保存。

当前真实场次参考值：

```text
72 个压缩帧合计：约 15.57 MiB
共享压缩网格：约 1.31 MiB
```

## 6. 命令说明

工具包含四个子命令：

| 命令 | 作用 |
|---|---|
| `convert` | 将 DAT 和 Shapefile 转成发布包 |
| `validate` | 独立校验已有发布包 |
| `publish` | 断点续传已有发布包 |
| `run` | 依次执行转换、校验和发布 |

生产运行推荐使用 `run`。排查问题或网络暂时不可用时，可以先 `convert`，之后再 `publish`。

### 6.1 convert 参数

| 参数 | 必填 | 默认值 | 说明 |
|---|---|---|---|
| `--dat-dir` | 建议显式填写 | 自动匹配 `AREA_RST_WUV_*/*.DAT` | 包含本场次所有 DAT 的目录 |
| `--grid-shp` | 是 | 仓库内默认网格 | WGS84 Polygon `.shp` 路径 |
| `--output` | 建议显式填写 | `.tmp/flowfield-package` | 转换包输出目录 |
| `--source-run-id` | 生产必填 | 首时次生成值 | 模型运行唯一标识 |
| `--scenario-name` | 建议填写 | 根据首时次生成 | 前端显示名称 |
| `--model-version` | 是 | `unknown` | 模型版本、方案或参数版本 |
| `--verify-source` | 强烈建议 | 关闭 | 转换后随机回读 DAT，对比量化误差 |
| `--verify-samples` | 否 | `10` | 源数据随机抽样数量 |
| `--allow-irregular-time` | 否 | 关闭 | 允许非逐小时时次，但仍要求严格递增 |
| `--force` | 否 | 关闭 | 覆盖已存在的输出目录 |

除非项目明确使用非逐小时结果，否则不要使用 `--allow-irregular-time`。

### 6.2 validate 参数

| 参数 | 必填 | 说明 |
|---|---|---|
| `--package` | 是 | `convert` 生成的发布包目录 |

### 6.3 publish 参数

| 参数 | 必填 | 默认值 | 说明 |
|---|---|---|---|
| `--package` | 是 | 默认输出目录 | 待发布的数据包 |
| `--server` | 是 | 无 | 服务根地址，必须包含 `/flow-field` |
| `--workers` | 否 | `4` | 并发上传帧数 |
| `--retries` | 否 | `5` | 单次上传失败后的重试次数 |
| `--timeout` | 否 | `60` | 单个 HTTP 请求超时秒数 |

## 8. sourceRunId 规则

`sourceRunId` 是发布幂等键，必须满足：

- 同一次模型运行始终使用同一个值。
- 不同模型运行绝不能重复。
- 建议只使用英文字母、数字、短横线和下划线。
- 不要把脚本执行时间作为 `sourceRunId`。

推荐格式：

```text
模型简称-起报时间-方案版本
```

示例：

```text
RST-WUV-202607110800-v1
```

重复发布同一个 `sourceRunId` 时：

- 若场次已经是 `READY`，服务端直接返回已发布。
- 若上传未完成，脚本只补传缺少的文件。
- 若场次已经归档，重新上传后会恢复为 `READY`。
- 若同一 `sourceRunId` 的数据内容发生变化，服务端拒绝发布。

模型结果确实发生重算或修改时，必须使用新的 `sourceRunId`，例如：

```text
RST-WUV-202607110800-v2
```

## 9. 上传令牌

令牌只能通过环境变量提供：

```text
FLOW_PUBLISH_TOKEN
```

脚本没有命令行令牌参数，也不会从配置文件读取。

安全要求：

1. 不要把令牌写进脚本。
2. 不要把令牌提交到 Git。
3. 不要把令牌放进 DAT 目录或发布包。
4. 不要在工单、截图或日志中展示完整令牌。
5. 发布完成后清除当前 Shell 中的环境变量。

## 12. 脚本自动校验内容

转换阶段检查：

- DAT 和 Shapefile 单元数一致。
- 所有 DAT 的 `N/E` 一致。
- 第一个 ZONE 和后续 ZONE 数字数量正确。
- 连接表节点范围正确。
- Shapefile Polygon 类型、单 Part 和闭合环。
- DAT 连接表与 Shapefile 环点能够重建相同节点。
- 所有时间严格递增。
- 默认逐小时连续。
- Z1/U/V 不含 `NaN/Inf`。
- 水位和流速量化不溢出 `int16`。
- 干湿状态。

发布包校验：

- 0 开始的连续帧序号。
- 每帧原始长度为 `E * 3 * 2`。
- 压缩长度。
- 压缩文件 SHA-256。
- gzip 可正常解压。
- 解压后长度。
- 解压后原始数据 SHA-256。
- 网格 `FFM1` 文件头。
- 网格节点、单元和三角形数量。

指定 `--verify-source` 后，还会随机选择时次和单元，将解码结果与原始 DAT 对比。

允许误差：

```text
水位：不超过 0.01 m
U/V：不超过 0.001 m/s
```

## 13. 正常成功日志

成功转换应至少看到：

```text
VALIDATE PASS: 72 frames, 15.xx MiB
SOURCE VERIFY PASS
```

成功发布应看到：

```text
PUBLISH PASS: scenarioId=...
```

没有出现 `PUBLISH PASS` 时，不应认为发布成功。

## 14. 常见错误处理

### 14.1 未找到 DAT

```text
未找到 DAT 文件
```

检查：

- `--dat-dir` 是否指向目录而不是单个文件。
- 扩展名是否为 `.DAT` 或 `.dat`。
- 运行账号是否有目录读取权限。

### 14.2 DAT 头缺少 N/E

检查文件开头 1024 个字符内是否存在：

```text
N=节点数, E=单元数
```

### 14.3 ZONE 未解析

检查标题是否包含完整日期和时间：

```text
ZONE T="YYYY-MM-DD HH:MM:SS"
```

### 14.4 token 数量异常

通常表示：

- DAT 字段顺序变化。
- Tecplot 输出从 BLOCK 改成 POINT。
- 后续 ZONE 重复输出了网格。
- 某个时次数据不完整。

不要通过修改脚本中的期望数量绕过。

### 14.5 Shapefile 与 DAT 单元数不一致

必须重新取得与该模型网格完全对应的 Shapefile。不能删除要素、增加要素或重新排序后继续发布。

### 14.6 节点重建冲突

可能原因：

- Shapefile 要素顺序改变。
- DAT 连接表改变。
- Shapefile 不是当前模型网格。
- 相邻单元公共边坐标不一致。

### 14.7 时次不连续

检查多个 DAT 的文件名排序和 ZONE 时间。默认必须逐小时连续。

不要仅为了通过校验就增加 `--allow-irregular-time`；应先确认业务确实允许非逐小时数据。

### 14.8 NaN/Inf 或量化溢出

这是模型结果数据错误或单位错误。应检查模型输出，不应修改脚本让异常值通过。

### 14.9 401 上传令牌无效

检查：

- 是否设置 `FLOW_PUBLISH_TOKEN`。
- 是否与服务端令牌一致。
- 环境变量值前后是否包含空格或引号。

### 14.10 403 仅允许内网访问

当前请求来源不是项目内网。请通过项目 VPN、专线或指定内网发布节点访问。

### 14.11 网络中断

保留整个转换包，再次运行相同 `publish` 命令。脚本会查询服务器进度并只上传缺少部分。

## 15. 发布前检查清单

- [ ] DAT 已完整生成且模型计算进程已关闭文件。
- [ ] 本场次所有 DAT 已放入同一个独立目录。
- [ ] DAT 文件名排序与时间先后顺序一致。
- [ ] 各 ZONE 时间严格逐小时递增。
- [ ] Shapefile 是当前模型网格，单元顺序未改变。
- [ ] `sourceRunId` 唯一且稳定。
- [ ] `scenarioName` 和 `modelVersion` 已填写。
- [ ] 使用了 `--verify-source`。
- [ ] 日志出现 `VALIDATE PASS` 和 `SOURCE VERIFY PASS`。
- [ ] 发布成功后日志出现 `PUBLISH PASS`。
- [ ] 上传令牌已从当前 Shell 清除。
- [ ] 原始 DAT 继续由河口院归档保存。

## 16. 发布后的数据保留说明

项目方服务器只保留最近 100 个可直接渲染场次的压缩帧。

更早场次会被标记为 `ARCHIVED` 并删除帧文件，但 PostgreSQL 中仍保留场次和校验元数据。

需要重新查看归档场次时：

1. 从河口院原始 DAT 归档中恢复该模型结果。
2. 使用原来的 `sourceRunId` 再次运行转换和发布。
3. 服务端完成校验后将该场次恢复为 `READY`。

因此，河口院不能因为发布成功就删除原始 DAT。
