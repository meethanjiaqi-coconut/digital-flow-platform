# 粒子缩放覆盖与拖尾调节修复

日期：2026-11-16。适用工程：`digital-flow-field/tdesign`。

后续核查发现，本文记录的拖尾修复尚未覆盖早期粒子移动尺度的变化；涌潮分界问题的进一步定位见 [粒子涌潮分界回归定位与修复](./粒子涌潮分界回归定位与修复.md)。

## 修复内容

1. 原实现改变流场采样范围后，没有重新分布已有粒子。缩小视图时，粒子集中在之前的局部范围；暂停时不会通过后续运动补充新区域。现在视野范围显著变化后，在新的湿区重新分布粒子，独立于播放时钟执行。
2. 原地平线剔除将地球视为赤道半径球体，钱塘江低空视角会被误认为位于球体内部。现在使用椭球三个半轴进行缩放空间遮挡计算，修复近景粒子实际存在却全部被剔除的问题。
3. 相机变化时清理旧屏幕拖尾，避免原位置的残影叠到新画面；条带增加域外和干区裁剪。
4. 面板增加“粒子拖尾”：短 0.4 秒、中 1.5 秒、长 3.0 秒；滑块范围 0–3 秒、步长 0.1 秒，0 表示无拖尾。
5. 拖尾按动画经过的时间衰减。RGBA8 纹理采用随动画变化的亚字节舍入，避免微弱尾迹因量化一直残留。
6. 暂停时修改拖尾会按当前 U/V 方向预览长度；不改变粒子位置和模型时刻。该预览是局部流向的视觉线段，实际播放继续积累运动历史。

## 使用

刷新页面，在“图层显示 → 流向粒子”下方调整“粒子拖尾”。粒子密度和线宽仍独立可调。关闭粒子后，相应控件禁用。

## 后续修正：恢复备份默认参数与播放流线（2026-11-16）

用户反馈播放画面变成光点。本轮核对两个完整备份中的 `ParticleFlowLayer.js`，参数一致：

| 参数 | 备份及当前默认值 |
| --- | --- |
| 粒子纹理边长 / 粒子数 | 128 / 16,384（面板显示约 1.6 万） |
| 面板线宽 | 1.0 像素 |
| 合成透明度 | 0.65 |
| 拖尾保留系数 | 60 FPS 时每步 0.95 |
| 面板拖尾时长 | 约 1.5 秒（衰减至约 1%） |
| 共享流动强度 | 原有默认 2.0 倍，未改变模型 U/V |

对照备份：`D:\git_repo\_backups\digital-flow-field-before-tidal-turbidity-20261115-021855`、`digital-flow-field-before-tidal-refinement-20261116-003731`。本轮改动前的三份实现文件和检查脚本保留在 `.tmp/particle-defaults/before/`。

### 真正原因与修正

密度、线宽的源码默认值本来已与备份一致；用户截图中选中的是约 6.5 万、1.4 像素、0.4 秒短拖尾。仅恢复这些数字还不足以解决播放问题。

实际绘制诊断发现，SuperMap 每帧先调用水面镜像辅助绘制，再调用主场景绘制。两次都是 `passes.render=true`，但辅助绘制标记为 `fboEnable=true / fboName=water`，相机矩阵也不同。上一轮逻辑把两次矩阵变化都当作用户移动相机，反复清空屏幕拖尾；辅助绘制还提前消耗动画时间，使主画面落入暂停预览路径。上一轮暂停状态的控件检查没有覆盖这个问题。

现在粒子层跳过辅助 FBO 和 offscreen 绘制，仅在主视图更新和合成。保留缩放重新分布、椭球遮挡、干区裁剪以及真实相机变化时清理旧屏幕残影的修复。拖尾按经过时间衰减，默认在 60 FPS 下严格对应备份的 0.95。默认值集中管理，面板增加“恢复默认粒子”，同时恢复密度、线宽、透明度和拖尾；水面设置与预报时刻不受该按钮影响。

### 本轮验证

- 修改前静止相机 180 帧触发 360 次拖尾绘制；修复后 210 帧中主视图和辅助视图各调用 210 次，但仅有 210 次拖尾绘制。
- 实际播放状态点击短、长按钮：有效拖尾像素分别为 13,023、75,270；默认参数为 40,845。数值是同一视角的可见变化证据，不代表物理流速指标。
- 暂停时按钮和滑块仍有效，调整样式不改变粒子位置哈希和动画时间；六组缩放、平移、旋转及播放中缩放检查通过，实际画布均有有效粒子像素。
- “恢复默认粒子”从 256 / 1.4 / 0.4 恢复至 128 / 1.0 / 1.5；独立生产预览也验证了初始值及恢复按钮。
- `check_particle_controls.mjs` 补充辅助绘制隔离和备份默认值回归检查，与 `check_playback_pause.mjs`、`check_water_dynamics.mjs`、`check_tidal_water_mix.mjs` 均通过。
- `npm.cmd run build:demo --prefix tdesign` 成功，最新主产物为 `flow-field-DlC4tApg.js`；生产预览确认实际加载该文件。
- 本轮浏览器记录无页面、场景或 WebGL 错误。验证为本机浏览器与本地生产预览，未进行远程部署。

证据位于 `output/playwright/`：`particle-defaults-after.png`、`particle-defaults-panel.png`、`particle-defaults-motion.mp4`（10 秒真实播放）、`particle-defaults-validation.json`、`particle-defaults-qa-zoom-trail-validation.json`、`particle-defaults-production.json`。
