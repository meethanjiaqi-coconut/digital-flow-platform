# SDK 的在线与离线交付

当前版本：`0.1.0-alpha.2`。构建完成后可执行 `npm run pack:local`。私有 GitHub 仓库随示例保存数据与引擎，npm 包另行交付。

## 推荐交付方式

对后续开发单位提供同一个版本的 npm 包；在线和离线只是获取渠道不同。

| 方式 | 开发单位获取方式 | 适用情况 |
| --- | --- | --- |
| 私有 npm 仓库（推荐） | 配置组织仓库后，`npm install @digital-flow/sdk@0.1.0-alpha.2` | 可访问企业网络或授权外网；能分配只读账号 |
| 离线 `.tgz` | `npm install ./digital-flow-sdk-0.1.0-alpha.2.tgz` | 无法连仓库的内网环境；版本可独立留档 |
| 静态文件服务 | 把包中的 `dist/`、`assets/` 按原结构发布，用 ESM/import map 引用 | 不使用 npm 的原生网页；服务需保持版本目录 |

Vue 业务系统按需再安装 `@digital-flow/vue-tdesign`。Vue/TDesign 依赖也需要可用的离线缓存或私服；`.tgz` 不自动打包所有宿主依赖。

## 在线发布前的具体步骤

1. 确定公司可维护的私有 npm 仓库地址与 `@digital-flow` 命名空间权限，例如现有制品库的 npm 仓库。需要让开发单位访问该网络。
2. CI 使用发布账号；开发单位仅配只读 token。参考根目录 `.npmrc.example`，token 放环境变量。
3. 先执行 `npm ci`、`npm run build`、`npm test`、`npm run typecheck`、`npm run pack:local`、`npm run verify:packages`，核对包内容与 SHA-256。
4. 由维护方在确定的仓库发布已核对的包：`npm publish artifacts/digital-flow-sdk-0.1.0-alpha.2.tgz --registry=https://实际仓库地址/ --tag=alpha --access=restricted`。再发布相同版本 UI 包。这里是待执行说明，本次未运行。
5. 从另一个干净项目按明确版本安装并打开接入示例。Alpha 用 `alpha` 标签；正式验收后才发布稳定版本。

## 引擎与数据单独交付

SDK npm 包只包含自有代码、Worker 和有来源说明的水面纹理。SuperMap3D/W3D 由宿主按自身授权提供，版本指纹见 `runtime-manifests/supermap3d-w3d-tested.json`。模型数据通过业务接口或静态文件服务提供，不塞进 SDK。

本私有仓库的 `local-assets/` 用于克隆后运行示例。交付 npm 包时，需向开发单位提供其可访问的数据地址和授权运行时地址。纯离线使用需同时部署本地引擎、数据与底图，示例卫星底图当前访问在线 ArcGIS 服务。

## 版本与升级

消费方锁定确切版本并保留 lockfile。SDK 和 UI 包同步版本发布。归档 `.tgz`、包摘要、运行时指纹和验证记录，出现问题可回退指定版本。不要在同一个版本号下覆盖产物。
