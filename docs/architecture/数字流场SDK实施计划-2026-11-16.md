# 数字流场 SDK 实施计划

日期：2026-11-16。状态：方案复核，尚未开始 SDK 拆分。本计划更新 2026-11-12 的《数字流场组件化评估与完整方案》，以当前五分钟流场和清浊交界锯齿修复后的源码为迁移基线。

## 1. 要交付什么

采用“流场 SDK + 可选 Vue 控件包”。接入项目提供已有 Viewer、兼容引擎运行库、数据源和配置，即可加载流场、播放、调节效果、查询和卸载。

| 交付项 | 内容 |
|---|---|
| `@digital-flow/sdk` | 框架无关的接口、数据源、播放、查询、SuperMap3D 渲染适配、可选河口潮头扩展；ESM、类型声明、Worker、SDK 自有纹理 |
| `@digital-flow/vue-tdesign` | 当前风格的控制面板、时间轴、场次选择、图例、查询弹窗；既可组合使用，也可单独使用 |
| 引擎资源清单 | 已验证的 SuperMap3D/W3D 组合、资源路径、指纹、能力和限制；沿用宿主已有引擎与授权资源 |
| 示例与说明 | 原生 JS、Vue、当前演示页、钱塘江现有数字流场入口的接入说明及升级回滚说明 |

包名暂定。逻辑上分层，物理上先保持两个包。Python 数据转换和 Java 服务独立维护，首版继续使用现有模型数据协议。

首版正式支持已有 SuperMap3D Viewer、桌面浏览器、同页单个活动流场实例。为其他引擎和多实例留接口，但需分别验收后再声明支持。

## 2. 这次复核对旧计划的修正

| 当前核查结果 | 实施调整 |
|---|---|
| `flowTime.js` 已按 Manifest 真实时刻插值；当前 1 倍为每两秒一个输出间隔 | 保留现有效果播放节奏。对外新增真实时刻 `seek`，明确帧序号和模型时间；旧计划的“1 倍每秒推进 1800 模拟秒”不再作为当前默认值 |
| 已有连续潮头跟踪、共用交界坐标、清浊混合、浑水历史与衰减 | 作为完整河口扩展迁移；随机跳转必须重建必要历史，不可只重置一个显示缓存 |
| 已有细浪、岸线过渡、场景倒影、交界抗锯齿 | 全部进入视觉基线；渲染封装包含颜色/深度捕获和相关引擎兼容代码 |
| Worker 直接 `fetch(state.frameUrl + index)` 读取历史帧 | 统一走 Provider 和请求调度；主线程提供鉴权后的二进制数据，Worker 专注计算，避免两套请求配置 |
| `qiantangjiang/src/widgets/DigitalFlowField/` 已有另一套复制代码 | 首个业务迁移点明确为该入口，由安装 SDK 包替代复制实现；保留宿主入口与布局 |
| SDK 目录、统一入口与发布产物尚未形成 | 目前是可复用实现基础，不能描述为 SDK 已完成 |

旧交接说明中的“首屏只读两帧”描述基础水动力加载。启用浑水历史并直接跳到较晚时刻时，还需要读取此前必要的历史帧；SDK 应显示该阶段进度并支持取消。

## 3. 功能范围与分层

```text
宿主业务页面 / 可选 Vue 面板
            ↓ 公开 API + 状态事件
流场会话：场次、播放、查询、配置、生命周期
     ├─ Provider / 请求调度 / 缓存 → 现有 HTTP 或静态分帧数据
     ├─ Worker → 节点聚合、潮头跟踪、浑水历史
     └─ SuperMap3D 适配 → 水面、粒子、箭头、潮头、倒影
```

SDK 首版保留：

- 五分钟数据、原逐时数据、相邻帧插值、播放暂停、倍速、拖动和缓冲状态。
- 河口水面、水位/流速着色、水面流向箭头、高程夸张、质量档位。
- 粒子显隐、数量、线宽；水面流动强度、细浪和倒影控制。
- 潮头标记、清浊交界、潮后浑水搬运与消退、不确定状态。
- 场次列表、点选当前值、完整过程线、场次切换、隐藏恢复和销毁。

潮头与浑水作为可选扩展。通用 SDK 不默认套用钱塘江区域。`qiantangProfile` 保存现有分析区、入海口方向、阈值、材质空间锚点与展示默认值；其他模型需要自己的配置和验证。

水面颜色继续区分模型派生示意、手动视觉预设和实际业务数据。SDK 封装不改变潮头判识的准确性边界，也不把浑水颜色解释为实测含沙量。

## 4. 接入方式和接口草案

以下为拟实现接口，目前不可直接安装调用：

```ts
import { createFlowField } from '@digital-flow/sdk'
import { createHttpProvider } from '@digital-flow/sdk/providers/http'
import { createSuperMap3DRenderer } from '@digital-flow/sdk/supermap3d'
import { createTidalEstuary } from '@digital-flow/sdk/plugins/tidal-estuary'

const flow = createFlowField({
  renderer: createSuperMap3DRenderer({
    viewer,
    runtime: { SuperMap3D, w3d },
    assets: runtimeAssets,
  }),
  provider: createHttpProvider({
    baseUrl: '/flow-field',
    request: authenticatedFetch,
  }),
  extensions: [createTidalEstuary({ profile: qiantangProfile })],
  playback: { autoPlay: false, rate: 1, secondsPerFrame: 2 },
})

const unsubscribe = flow.on('statechange', updatePanel)
await flow.loadScenario({ sourceRunId: planId })
flow.play()
await flow.seek('2026-10-25T01:20:00+08:00')
flow.setOptions({ particles: { visible: true, count: 16384, lineWidth: 1 } })
const result = await flow.queryAt({ lon: 120.4, lat: 30.3 })

// 页面卸载时：
unsubscribe()
await flow.destroy()
```

`viewer`、`runtimeAssets`、`authenticatedFetch`、`qiantangProfile` 和 `planId` 来自宿主配置或示例配置。业务 `planId` 与 `sourceRunId` 的对应关系由宿主明确提供。

| 接口组 | 主要能力 |
|---|---|
| 加载 | `listScenarios`、`loadScenario`、加载取消、错误重试 |
| 播放 | `play`、`pause`、`setPlaybackRate`、`seek`、循环配置 |
| 效果 | `setOptions`、`setVisible`、实际能力和限制查询 |
| 查询 | `pick`、`queryAt`、`querySeries` |
| 状态 | `getState`、`on`；加载、显示时刻、缓冲、场次、潮头状态、错误 |
| 资源 | 幂等 `destroy`、诊断计数、资源占用统计 |

公开状态区分用户请求时刻与实际显示时刻。时间轴、查询值、潮头和水面在同一次显示提交中保持一致。流动强度属于视觉设置，不改变查询 U/V；播放倍速单独控制数据推进。

SDK 默认不自动移动相机、不替换宿主点击功能、不修改宿主时钟。当前演示页可以显式开启原有自动播放和定位策略。

Vue 包提供两种方式：完整 `<DigitalFlowField>` 负责创建和销毁 SDK；独立 `<FlowControls :flow>`、`<FlowTimeline :flow>` 等只订阅已有实例。保持钱塘江 UI 风格，面板宽度、位置、颜色、层级可配置，粒子调节入口必须保留。

## 5. 必须处理的封装点

| 工作 | 实施要求 |
|---|---|
| 统一门面 | 页面不再手动组装 Data、Controller、水面、粒子和潮头；UI 不访问 `controller.water` 等内部对象 |
| 数据与鉴权 | 基础帧和历史帧共用 Provider；传递取消信号，兼容 Token 更新、二进制响应和去重；旧场次回包不能污染新场次 |
| Worker 通信 | 使用任务 ID、场次代次、消息协议传数据；缓存拥有者和可转移缓冲区分开，避免转移后主线程缓存失效 |
| 历史一致性 | 保留确定性顺序重建；顺序播放、直接跳转、随机回看在同一数据/参数版本下结果一致；检查点优化后续按规模引入 |
| 引擎适配 | 将 W3D 私有成员、着色器注入、颜色/深度捕获集中到兼容层；锁定已验证引擎组合，异常初始化也能回滚 |
| 共享场景 | 明确 `_waterPassEvent`、场景坐标和命令包装等共享状态的安装、恢复责任；验证不破坏宿主其他图层和点击行为 |
| 资源路径 | 移除公共 SDK 中的固定 `/libs/`、`/textures/`、项目别名和 API 环境变量；通过运行时资源配置和包内相对路径定位 |
| 资源释放 | 请求、Worker、监听、纹理、帧缓冲、图层精确归属；销毁可重复执行，只清理本实例拥有的资源 |
| 模型约束 | 协议、坐标/高程/单位、节点容量、潮头适用条件显式校验；扩展未配置时保留普通流场能力 |

Worker 在独立上下文中运行，不能把主线程请求函数直接作为普通消息传入；数据通过消息协议传递。Worker 文件以 SDK 模块相对路径定位，并提供 `workerUrl`/`workerFactory` 供特殊部署使用，参考 [MDN Worker 消息与资源路径说明](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Using_web_workers)。

## 6. 实施顺序与阶段出口

| 阶段 | 要完成的工作 | 可检查的结果 | 前端估算 |
|---|---|---|---:|
| M0 固定基线与契约 | 保存当前修复版、运行资源指纹；冻结 API、配置、所有权；录制远近景、潮头推进和面板操作 | 功能/视觉/性能基线、接口草案、明确的回滚入口 | 2–3 人日 |
| M1 核心与数据 | 建立 SDK 入口、Provider、状态事件、真实时刻查询、请求取消和 Worker 数据通道 | 不依赖 Vue 的加载、调度和查询；鉴权与乱序回包验证 | 5–7 人日 |
| M2 渲染适配 | 迁入当前水面、粒子、箭头、倒影；抽出运行库兼容层、资源路径和生命周期 | 原生 JS 示例使用同一 Viewer 展示流场，普通效果对照通过 | 6–8 人日 |
| M3 河口扩展 | 封装跟踪、交界、浑水历史、区域配置、状态与材质数据；保留抗锯齿修复 | 当前完整河口效果通过 SDK 运行，随机跳转结果一致 | 3–4 人日 |
| M4 UI 与项目迁移 | 独立控件和组合组件；当前演示页先迁移，再迁移钱塘江 DigitalFlowField 入口 | 两个项目安装同一包；业务入口、布局及调节项保留 | 4–5 人日 |
| M5 打包与交付 | `.tgz`、类型、Worker/资源；干净工程安装；目标环境、性能及销毁验收 | 安装即可接入的包、示例、文档、兼容表与验收报告 | 4–5 人日 |

前端估算合计 **24–32 人日**，延续原方案量级；另外预留服务/网关联调约 2–3 人日、专项测试约 4–7 人日，总投入约 **30–42 人日**。假设当前渲染能复用、一个正式引擎组合、数据协议保持不变。两名互补开发配合测试和服务端时，建议按 **4–6 周**规划；这是人员投入估算，不是自动化执行时长承诺。首个阶段结束后根据引擎兼容与宿主接入结果复核排期。

M2 出普通流场接入样例；M3 出含当前清浊效果的完整 SDK 候选版；M5 才构成可交付版本。

## 7. 怎样认定完成

| 验收方面 | 必须达到的结果 |
|---|---|
| 效果不退化 | 当前水色、流动、粒子、近岸过渡、细浪、倒影、清浊交界与抗锯齿均有同数据同视角对照 |
| 数据与时间 | 144 个五分钟时次及原逐时样例；首末帧、暂停、倍速、快拖、缺帧、过期回包；物理值与视觉参数分离 |
| 潮头历史 | 顺序与随机跳转同帧历史校验一致；连续跟踪/待确认/残留状态正确；启停扩展不显示旧场次结果 |
| 接入独立性 | 原生 JS、Vue 干净目录安装 `.tgz` 可运行，不依赖原仓库源码别名；核心无 Vue/TDesign 依赖 |
| 资源与部署 | 根目录、子目录部署及配置 API 地址；Worker、纹理、引擎资源没有 404；带鉴权历史读取可用 |
| 宿主兼容 | 钱塘江现有 Viewer、业务图层、点击工具、相机和时钟正常；引擎差异按实际组合验收 |
| 生命周期 | 挂载卸载 20 次、场次切换 50 次、连续播放 30 分钟；自有资源清理完整，无持续增长与晚到回调写入 |
| 性能 | 同设备、数据、画质和路径对比当前基线，稳态 FPS 降幅目标不超过 10%；冷/热加载、历史重建耗时单独记录 |

上述为实施阶段验收目标，不是本次已经执行或全部通过的结果。旧页面的测试记录只能用作迁移基线，不能替代 SDK 产物验收。

## 8. 迁移和回滚

在 `digital-flow-field` 新增 `packages/sdk`、`packages/vue-tdesign`、`examples`。旧入口保留，SDK 使用单独入口验证；同一 Viewer 避免同时挂两套流场。先让当前演示页消费 SDK，再将钱塘江 `src/widgets/DigitalFlowField/DigitalFlowField.vue` 改为宿主接线，沿用其 `VIEWER_INJECT_KEY` 获取 Viewer。

迁移期间只保留一处持续演进的流场实现。新旧对照版本用固定快照保存；默认入口切换前保留旧版回滚路径。回滚时先销毁 SDK 实例，再恢复旧入口和匹配的引擎资源版本。

首版暂缓多引擎、多实例、移动端、超现有节点容量扩容、WebGPU 重写和新水动力模型求解。这些单独立项，不作为两个 SDK 包能否交付的前提。
